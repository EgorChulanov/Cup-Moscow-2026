# Инструкция для всех, кто работает в репозитории (люди и ИИ-модели)

Это рабочий репозиторий команды на кейс-чемпионате **Changellenge >> Cup Moscow 2026**, секция **Т-Банк**, первый тур.
Кейс: «За сообщением клиента: предложите подход к работе специалиста клиентской поддержки Т-Банка».

Прежде чем что-то менять, прочитай по порядку:
1. [docs/CASE_BRIEF.md](docs/CASE_BRIEF.md): что спрашивает кейс (7 подзадач) и факты из кейса.
2. [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md): формат сдачи и критерии оценки. Это закон.
3. [docs/STATUS.md](docs/STATUS.md): что уже сделано, что в работе, открытые вопросы. **Обновляй его после каждой сессии.**

## Сдача

- Один PDF до 18 МБ, загружает один участник в личном кабинете до **2 ноября 2026, 12:00 МСК**.
- Основная часть: **ровно 8 слайдов**, включая титульный и слайд с резюме команды. Приложения не считаются и не ограничены, лучше внутри того же PDF.
- Имя файла: `CupMoscow2026-Т-Банк-<НазваниеКоманды>.pdf`. Excel-приложение называется так же.
- Ссылки на облако не принимаются.

## Где что лежит

| Папка | Что внутри |
|---|---|
| `docs/` | постановка, требования, статус, шаблон-обоснование для специалиста |
| `research/` | вторичные данные с источниками: отзывы, экономика поддержки, лучшие практики, открытые CJM, опрос, тренажёры |
| `analysis/` | наш анализ: дерево причин, типы ситуаций, варианты решения и их сравнение |
| `cjm/` | CJM и Service Blueprint: данные в `cjm.yaml`, сборка в HTML для приложения и для Miro |
| `model/` | финансовая модель (`build_model.py` собирает `.xlsx`) |
| `deck/` | презентация: `slides.html` (источник), `build.mjs` (сборка PDF), `out/` (готовый PDF) |

## Правила качества (из критериев жюри)

- **Отвечаем строго на вопросы кейса.** У каждой из 7 подзадач есть место в презентации, карта в `docs/REQUIREMENTS.md`.
- **Каждая цифра со ссылкой на источник.** Факт без источника помечаем «допущение» или «гипотеза».
- **Исследование честное.** Считаем людей, а не стикеры, и пишем «N из M», а не проценты. Не выдумываем ответы респондентов и результаты тренажёров. Если данных нет, так и пишем и ставим вопрос для проверки.
- **Единая логика:** проблема → причины (3–5 уровней) → типы ситуаций → 3–5 вариантов → сравнение по одной структуре факторов → выбор → финансы, риски, план → метрики.
- **CJM по шаблону нашей Miro-доски** (курс UX-исследований ВШЭ): этапы и шаги; дорожки «цель, действия, мысли, эмоции −2…+2, важность 1–3, причины оценок, точки контакта, барьеры, источник и статус, материалы»; ниже Service Blueprint (видимые действия, линия видимости, за кулисами, люди и системы). Статусы: Г (гипотеза), Н (наблюдение), О (отзыв или опрос), С (вторичный источник).
- **Слайды без избытка текста:** одна главная мысль в заголовке-выводе, деловой стиль, без опечаток.

## Стиль текста

- Русский язык, простые формулировки.
- Без длинного тире «—»: запятая, двоеточие или скобки.
- Без декоративных символов-разделителей вроде «·» в тексте слайдов.

## Git

- Работаем в ветках и сливаем в `main` через pull request, чтобы не перетирать друг друга.
- Сообщения коммитов на русском, по делу.
- Не коммитим PDF кейса и другие материалы организаторов целиком: кейс конфиденциален. В `docs/CASE_BRIEF.md` лежит наш пересказ.
- Не коммитим персональные данные респондентов: только обезличенные коды R01, R02.

## Как собрать

```bash
# финмодель
python3 model/build_model.py            # создаст model/out/*.xlsx

# презентация (нужны Node 18+ и Playwright с Chromium)
node deck/build.mjs                     # создаст deck/out/*.pdf и проверит размер
```
